# 2–3 分钟演示视频脚本（MiniTower QA 作品集）

> 目标：让面试官在 3 分钟内相信——"你会搭游戏质量保障体系，且所有结论有真实数据支撑"。
> 录制要点：OBS/录屏 1080p；先跑命令再讲（数字实时出现最可信）；语速 120–140 字/分。
> 全程可复现命令见脚本右栏；对应证据文档在 docs/ 下。

---

## 第 0 段：开场定位（0:00–0:20，约 60 字旁白）

**画面**：仓库 README 首页 + 目录树滚动
**旁白**：
"我为游戏测试岗做了一个自研项目：一套轻量塔防数值引擎 MiniTower，以及围绕它从
需求分析到 AI 辅助的完整质量保障体系——79 条自动化用例、5 份真实数据报告。"
**字幕要点**：MiniTower QA · 游戏数值质量保障体系

---

## 第 1 段：被测对象与确定性（0:20–0:50）

**画面**：`python -m mini_tower` 运行，展示 3 个场景结局 + 确定性校验
**操作**：
```bash
python -m mini_tower
```
**旁白**：
"引擎 headless 可跑、数据全 JSON 外置——改一行配置就是一次数值改动，可以当被测对象做回归。
seed 固定后逐事件可复现，这是后续一切统计结论可信的前提。"
**强调**：场景3 单近卫"漏3只但通关、非三星"→ 胜利/星级语义正确（BUG-001 回归）。

---

## 第 2 段：需求驱动测试 + 缺陷闭环（0:50–1:30）

**画面**：`docs/requirements.md`（REQ 编号）→ `docs/test-case-matrix.md` → 跑规则测试
**操作**：
```bash
python -m unittest tests.test_rules tests.test_tuning -v
```
**旁白**：
"每个断言都来自需求文档手工推导的黄金样本，而不是看实现抄的。这套测试曾经抓住过
真实缺陷——胜负判定漏路径（BUG-001），和两个受控演练缺陷（伤害下限、技能 off-by-one）。
每一条都有变红证据、根因、修复和回归用例锁定，复盘在 docs/defects.md。"

---

## 第 3 段：数值三件套 + SQLite（1:30–2:10，本段最高光）

**画面**：切到 `docs/w3-report.md` 的 SQL 结果表（Q1/Q2/Q4）
**操作**：
```bash
python scripts/w3_report.py      # 3600 局 + 100 万抽 → SQLite → 6 条 SQL
python scripts/w4_tune_demo.py   # 平衡故事线
```
**旁白**：
"数值层我做了三件事：2000 局蒙特卡洛把通关率和时长锁在设计区间；
招募概率用 200 万抽做 χ² 拟合优度与 95% 置信区间假设检验；
3600 局模拟落 SQLite，用 6 条 SQL 反哺调优——最直观的一条：高防关 1-2 里
'带真实伤害术师的编队 0 漏怪'，而'没有真伤的编队每局平均漏 1.7 只'，
这直接给出了'这个版本该练谁'的结论。"
**强调**：性能 0.09ms/局、×10 敌人耗时只 ×9.9（近线性），基线防回归。

---

## 第 4 段：改数值 → 红 → 调参 → 绿（2:10–2:40）

**画面**：`w4_tune_demo.py` 输出逐行出现
**旁白**：
"最有价值的一段：版本改动把惊雷攻击力砍 30%，临界编队三星率从 100% 掉到 43%，
平衡测试当场变红；我没有只报'坏了'，而是用二分搜索给出可执行建议——atk 不能低于 109，
采纳后回归绿。这就是测试左移、推动解决。"

---

## 第 5 段：AI 三道闸 + 收尾（2:40–3:00）

**画面**：`python scripts/w5_ai_demo.py` 输出（三条线 + 审计表）
**旁白**：
"AI 我做了三条线：需求拆测试点、数值风险评估、失败日志聚类。关键不是用了 AI，
而是给它上了三道闸：schema 结构化校验、数值建议用引擎实测交叉验证——AI 如果说
'至少 100'，引擎会拿实测的 109 驳回它；全程审计留痕。配 GitHub Actions 每日自动回归。"
**结尾**："我能把需求分析—用例设计—自动化—数据分析—AI 辅助—推动修复整条链路跑通。"
