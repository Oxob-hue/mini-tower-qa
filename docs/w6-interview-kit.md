## 1. 简历条目（中文版，可直接放"项目经历"）

  为其搭建覆盖 功能规则 / 数值 / 概率 / 性能 / 数据 / AI 的完整质量保障体系；

  黄金样本；测试曾发现并推动修复 3 处实现缺陷（含真实胜负判定 bug），复盘含红→根因→修复→回归；
- **数值三件套**：2000 局蒙特卡洛锁定平衡区间；招募概率 200 万抽 χ² 拟合优度(df=2)与

  （def=100 真伤优势 25×）；

- **AI 深度使用**：需求→测试点、数值改动风险评估、失败日志聚类三条线；AI 产出过三道闸

## 2. 追问与应答（面试官最可能问的 15 个）

### 方法 / 理论
1. **"断言区间哪来的？"**
   → REQ-BAL 设计目标 + 蒙特卡洛基线校准（`docs/requirements.md` §2.7），不是拍脑袋；
   平衡测试时长带 (24,33)/(52,58) 就是这么来的。
2. **"为什么用 χ² 不用别的？"**
   → 三档稀有度拟合优度，自由度 2；样本量 200 万、期望频数≫5 满足适用条件；
   想更精确可换二项精确检验或加 scipy 给 p 值，结论一致。
3. **"蒙特卡洛模拟能代表真机吗？"**
   → 引擎验证的是**数值/规则层**（公式、概率、平衡），手感与表现层仍需人工探索测试；
   两者互补。确定性 seed 保证回归可比。
4. **"如何证明引擎没按测试写反（同源偏误）？"**
   → 黄金样本先于实现手工推导（需求→公式→手算→断言）；发现 BUG-002/003 即证明测试独立于实现。

### 缺陷 / 工程
5. **"三个缺陷都是真的吗？"**
   → BUG-001 是演示时真实触发并修复的；BUG-002/003 是按方案"诚实设计建议"做的受控演练，
     目的是展示完整缺陷闭环；每一个都有真实变红输出与回归用例。
6. **"测游戏为什么要自研引擎？"**
   → 完整演示需求方+实现方+测试方闭环；数值/概率测试需要内部可见、seed 可控的被测对象；
     另规划了开源项目支线补"测陌生代码库+对外 PR"的外部性（见求职方案 §2.5）。
7. **"性能测试会不会被机器波动骗了？"**
   → 用相对伸缩比（×10 敌人 ≈×9.9）而不是绝对阈值；基线比对带机器指纹 + 1.5 容忍系数。

### 数值 / 概率
8. **"保底概率怎么验证的？"**
   → 分两层：关保底用 χ²/CI 验"基础概率与声明一致"；开保底验整体率抬升（2%→2.89%）与
     max 间隔 ≤100 的保底语义。
9. **"为什么改惊雷 30% 就掉三星？"**
   → 临界编队恰好贴着 95% 三星线的悬崖，削输出直接漏铁壳；这也是"测出问题+给区间"故事的来源。
10. **"SQL 分析除了看结论还有别的用吗？"**
    → 测试产物可落库可回放，是 CI 每日回归与"最强编队漂移检测"的数据基础；面试强调"数据反哺调优"闭环。

### AI
11. **"AI 输出万一错了呢？"**
    → 三道闸：schema 校验拒绝非法输出；数值建议用引擎实测交叉验证（AI 说 100，
       引擎实测 109 → 驳回自动修正）；人工复核留痕，全链路审计。
12. **"没 API Key 怎么演示？"**
    → 提供者可插拔：本地规则提供者让管线离线可复现（测试/CI 不依赖外部），
       配 Key 后只换"初稿生成器"，闸门一字不改。

### 行为 / 表达
13. **"介绍一次你推动别人解决问题的经历。"**
    → 用 4 段故事：发现（砍 30%→43%）→ 定位（数值悬崖）→ 给区间（二分 ≥109）→ 回归绿；
       强调"给可执行建议"而非只报 bug。
14. **"你最喜欢的游戏与测试有什么关系？"**
    → 我是《明日方舟》玩家；想从"玩家吐槽数值"变成"用测试与数学验证数值"——项目正是把
       塔防数值设计方法论（克制/保底/成长）搬进可测引擎。
15. **"如果给你一款真实手游，第一步测什么？"**
    → 先看需求/埋点与数值配置链路 → 搭确定性可复现环境（seed/时间）→ 从核心循环的
       数值结算与状态机入手做黄金样本，再上探索测试与性能基线——与本项目方法一致。
