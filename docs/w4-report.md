## 1. 性能基准（REQ-PERF-001/002/005）

机器指纹：`Windows 11 | Python 3.14.4 | Intel64 Family 6 Model 154 Stepping 3`

| 场景 | 局数 | ms/局 | 单局峰值内存 |
|---|---|---|---|
| 1-1 · 编队A | 2000 | **0.092** | 9.0 KB |
| 1-2 · 编队B | 2000 | **0.190** | 16.7 KB |

单局 < 5ms 绝对守卫与 <100MB 内存断言之外，引擎实测每局仅 0.1–0.2ms、
峰值内存 <17KB（含全量事件日志）——为 W3 十万级蒙特卡洛/百万抽留足余量。

## 2. 伸缩曲线（REQ-PERF-004）

同构压力关（敌人从出生点连发涌出）：

| 敌人数量 | ms/局 | 相对 300 只 |
|---|---|---|
| 300 | 7.28 | 1.0× |
| 3000 | 71.73 | **9.85×**（另组实测 500→5000 = 9.30×） |

**结论**：×10 敌人 → 耗时 ≈×9.3~9.9，近线性（O(n·log n) 的事件堆在量级上被
常数压住），无 O(n²) 退化风险；断言窗 (5,25) 留足机器差异。

## 3. 基线防回归（REQ-PERF-003/006）

`scripts/w4_bench.py` 重新测量并与 `results/baseline.json` 比对：
当前 ms/局 ≤ 基线 ×1.5 → PASS，否则 **FAIL(回归!)**。系数 1.5 吸收机器抖动，
基线含机器指纹避免跨机误报。W5 将接入 CI 每日定时执行。

## 4. 平衡调参故事线（REQ-BAL-005，JD 职责④⑤ 完整证据）

临界编队 **磐石 + 惊雷 @ 1-2**，设计目标：三星率 ≥95%。

| 步骤 | 数值 | 平衡测试 |
|---|---|---|
| 基线 | 惊雷 atk=140 → 三星率 100% | 绿 |
| **改动（超标）** | atk=98（-30%）→ 三星率 **43.1%**、通关率仍 100% | **红**（<95%） |
| 定位与建议 | 根因=惊雷输出不足致漏铁壳（掉星不掉通关）；二分（1000 局×搜索步）给 **atk ≥109（≈原值 77%）** | — |
| 采纳建议 | atk=112 → 三星率 **100%** | 绿 |

```
[改动 98]  三星率 43.1% < 95%  【平衡测试变红】
[建议]     atk ≥ 109（≈ 原值 77%），区间由测试二分给出，非拍脑袋
[采纳 112] 三星率 100.0% ≥ 95% 【回归绿】
```

**面试口径**：这就是"测试左移 + 推动解决"——测试不只报"坏了"，还给出
**可执行的建议区间**（二分搜索 + 设计目标线），数值改动在合入前就被拦下。
